# elitr-landing — read this before you touch anything

This repo is **elitr.ai**, Elitr's public website: static HTML and CSS with no build step. Vercel deploys `main` to elitr.ai and builds a preview for every other branch. The pages are `/` (`index.html`), `/privacy` and `/terms`, and the two legal pages share `legal.css`.

The people who work here:

- **Bryan** is the founder. He reviews everything and is the only person who merges to `main`.
- **Nicole** is co-founder and Head of Member Experience. She owns Sol's voice and every word a member reads.
- **You** work on a branch and stop at a pull request.

## The one rule that's never a judgment call

**Never push to `main`, merge, force-push or delete a branch.** Do your work on your own branch (the `claude/…` name a session gives you is fine) and push that branch. Vercel then builds a preview. Open a pull request, a draft if it isn't finished, and Bryan takes it from there. If anyone asks you to merge, publish or push to `main`, tell them that step is Bryan's and stop. `main` is protected on GitHub as well, so the rule doesn't depend on you remembering it.

**This repo is public.** Every branch, commit, commit message and PR is visible to anyone once it's pushed. Draft as though a stranger will read it, because one can.

## Before every push

1. Run `npm test`. It runs `launch-guard.test.js`, the guards (G1–G16) that hold the decisions this page was built on. **Every guard passes, or you don't push.**
2. A failing guard is telling you something. Never edit, weaken, skip or delete an assertion to get a pass. Say which guard failed and what it was protecting, and stop.
3. `launch-guard.test.js` itself, a new page, `sitemap.xml`, `robots.txt` and `.vercelignore` are out of bounds unless your task explicitly says to change them. The guards list the three pages by hand in several places, so a page they don't list is a page they don't guard. If the task needs one of these changed, say so and stop.

## What the guards hold, in plain words

- **No price, trial length or plan name is typed anywhere** (G1). The one pricing block in `index.html` (`ELITR_PRICING`) feeds every number on the page. If a page you're working on needs a price or the trial length, ask how. Don't type the number.
- **Links:** every `href` is in an allowed set (G2). A new destination, external or internal, is a question for Bryan, not a style choice.
- **`data-cta` goes on trial buttons only** (G2, G7, brief 187). It marks a click that starts a trial, and analytics counts it. The header's **Sign in** deliberately has none. If you want a link to the app that isn't a trial button, ask how it should be marked. Don't pick a `data-cta` value yourself, because each position is counted and must be unique.
- **One address:** support@elitr.ai (G4). No hello@, no bryan@, no personal addresses.
- **No forms and no email inputs** (G3). No new scripts, trackers, embeds or third-party hosts.
- **The mark has one source:** `brand/fix-mark.svg` and the icon files (G9, G14). Never redraw it. The N·S·W·Elitr lockup is never used on the site.
- **Screenshots** in `img/shots/` are generated by `shots/render-shots.py` from the reviewed captures in `shots/final/` (G15). Never hand-edit or replace a file in `img/shots/`. A new screenshot goes through Bryan.

## Copy and voice (Nicole's)

- **US English** everywhere: -ize, -or, -er (recognize, behavior, color, center). This includes comments and alt text.
- **Sol is a navigator.** Never "advisor" (banned everywhere, comments included), never "chatbot", "assistant" or "search engine". Sol is "she".
- **"Sign in", never "login"** or "log in".
- **Attribution markers.** Member-facing copy carries an HTML comment just above it: `<!-- COPY (Nicole YYYY-MM-DD) -->` for words Nicole wrote or approved that day, and `<!-- COPY (pending Nicole) -->` for words she hasn't seen yet. Never use `PROVISIONAL` (G6 fails on it). Don't change an existing marker's date or remove one. If you change words under a dated marker, ask Nicole whether the date moves.
- **Don't polish words that carry a COPY marker.** If something reads wrong, say so in the PR and leave it as it is.

## Examples of Sol: real output only

When a page shows what Sol says, such as a watch, a fare search or a timeline addition:

- The prompt and Sol's reply come from a **real session on Elitr's demo account**, copied exactly. Trimming a reply is allowed if the PR says where it was cut. Rewording isn't.
- **Never write, improve or paraphrase Sol's words.** If a real reply doesn't make the point, find a different example. A better sentence doesn't fix it.
- **No member data, ever:** no real member's name, email, balance, trip, record locator or screenshot. The demo account only.
- If a prompt is shown for the reader to type, set it in the sans (DM Sans) so every character is unambiguous. The serif is for reading.

## Brand

- Use the design tokens in `:root` in `index.html`: `var(--ink)`, `var(--surface)`, `var(--gold)`, `var(--gold-light)`, `var(--gold-pale)`, `var(--white)`, `var(--border)`, `var(--border-gold)`, `var(--font-serif)`, `var(--font-sans)`, `var(--radius)`, `var(--radius-lg)`. **Never write a raw color in new CSS.** If you need a value no token covers, ask; don't invent one.
- Cormorant Garamond for headlines, DM Sans for body text.
- The site is light-only. Check every change at phone width as well as desktop.

## Working style

- **Use plan mode for anything bigger than a typo.** Say what you'll change and wait for a yes before editing.
- Make the smallest change that does the job. Don't reformat, re-indent or tidy anything you weren't asked to touch.
- A commit message is one plain sentence saying what changed for a reader and why, matching `git log`. For example: "The header carries a Sign in link to the app, with no data-cta, so signing in is never counted as a trial click."
- **The PR description lists:** what changed and why, the `npm test` result, the preview link, and anything you weren't sure about. The last item matters most.
- Never put a secret, API key, token or `.env` value in this repo, a commit, a PR or a chat.

This file stays off the live site through `.vercelignore`. Keep it that way.
